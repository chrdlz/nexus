>> I think CORAL is an excellent choice for your project, and your interpretation of the metaphor makes it even stronger. Good infrastructure names usually work because the metaphor naturally explains the system, and CORAL does that very well.

Let’s look at why it fits so well.

1. The metaphor maps almost perfectly to your architecture

Your system concept already has a biological structure:

CORAL reef

Polyps → individual workers / agents

Branches → task flows / dependencies

Reef → the evolving ecosystem of agents and tools

Nutrient exchange → communication between agents

Growth → agents added over time

Your orchestrator is essentially the reef structure that allows the ecosystem to exist.

So:

agents = polyps
communication = nutrient exchange
workflows = branches
orchestrator = coral skeleton
ecosystem = workspace

That’s a very coherent mental model.

2. The acronym works naturally

Your acronym:

CORAL
Coordination Orchestration Runtime for Agent Layers

This is actually good because:

each word corresponds to a real component

it doesn’t feel artificially forced

it reads like infrastructure terminology

Breakdown:

Coordination → agents interacting
Orchestration → execution control
Runtime → execution engine
Agent Layers → abstraction over agents/tools

It sounds like something that could exist inside a larger system.

3. It feels like a subsystem, not a product

You mentioned you want the name to feel like a component of a larger system.

CORAL does that nicely.

Example future architecture:

Brain System
   ├─ Cortex
   ├─ Memory
   ├─ Tools
   └─ CORAL
        Agent orchestration layer

Or even:

Workspace AI Stack

CORAL → agent orchestration
PLANKTON → data ingestion
REEF → agent ecosystem

The marine theme can extend very nicely if you ever want to.

Your roadmap actually mirrors reef growth:

Stage 3 – workers and queues
→ ecosystem complexity

Stage 4 – agents interacting

So the name matches the way the system will grow.
